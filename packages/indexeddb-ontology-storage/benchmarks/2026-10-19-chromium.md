# Tables subset benchmark — 2026-10-19

macOS arm64, headless Chromium via Playwright 1.61.1; Node 24.14.0, Effect 4.0.5.

10,000 identical rows, three declared field indexes (including lowercase companions),
and matching queries. All four implementations are checked against the full-data
oracle before timing. Unordered results are compared as sets; explicit ordering
is checked exactly. Each benchmark runs at least five samples / 300 ms, after
two warmups / 50 ms. These are local development measurements, not CI thresholds.

Results use tagged field references and the simplified value-tree codec, with schema validation at storage boundaries.

Mean latency in milliseconds (lower is better):

| Query                       | Memory | Tables indexed IDB | Tables full-scan IDB | Existing persistence adapter |
| --------------------------- | -----: | -----------------: | -------------------: | ---------------------------: |
| equality / 100 matches      |  0.796 |              2.483 |               95.860 |                        1.783 |
| selective AND / 10 matches  |  0.517 |              3.198 |               98.440 |                       13.261 |
| empty AND                   |  0.026 |              1.273 |              101.400 |                        5.129 |
| OR / 1090 matches           | 12.168 |             27.636 |              119.180 |                       18.406 |
| IN / 300 matches            |  3.254 |              8.042 |              131.780 |                        5.197 |
| LIKE / 111 candidates       |  0.412 |              2.104 |               89.140 |                        1.974 |
| ILIKE / 111 matches         |  0.913 |              2.720 |               87.780 |                        2.178 |
| ascending page / 10 rows    |  0.134 |              1.068 |              102.420 |                        1.066 |
| descending page / tied keys |  0.155 |              1.319 |              148.380 |                        0.960 |

The planner substantially reduces work versus the full-scan path. Selective and
empty AND queries improve on the existing adapter by choosing a small candidate
set or stopping at a zero count. The new implementation is still slower on some
broader queries and tied descending pages. Further profiling should distinguish
Effect scheduling, encoding/decoding, and native request costs before optimizing.

Memory timings exclude worker messaging; no SharedWorker RPC is implemented.
The existing adapter stores additional cache/replication metadata and uses a
different row codec. Only subset-read workloads are compared here; these numbers
do not establish write throughput or cross-browser performance.
