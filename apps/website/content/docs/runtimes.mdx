---
title: Platform runtimes
description: Scoped platform capabilities and memory or persistent storage.
---

`@party-stack/web-runtime` provides a Runtime Layer. Storage mode is independent
of process placement: a tab, worker or another process can use memory or durable
storage, but each persistent namespace must have one designated owner.

```ts
import { Runtime, RuntimePartition } from "@party-stack/runtime";
import * as WebRuntime from "@party-stack/web-runtime";
import { Effect } from "effect";

const platform = WebRuntime.layer({ persistEncryptionKeys: true });
const inspect = Effect.scoped(
    Effect.gen(function* () {
        const runtime = yield* Runtime;
        return yield* runtime.connectivity.online;
    })
).pipe(
    Effect.provide(platform),
    Effect.provideService(RuntimePartition, { owner: userId, namespace: ontologyId })
);

const memory = WebRuntime.layer({ storage: "memory" });
```

Persistent mode uses IndexedDB tables and OPFS bytes. Memory mode provides
isolated tables, byte storage and ephemeral encryption keys. Scope closure releases
platform resources. Partition identity comes from `RuntimePartition`, rather than
being mixed into static platform configuration. Installations use `Runtimes.layer(platform)`
to acquire multiple partitions through LayerMap.

Platform Layers acquire tables explicitly, including memory tables; `Runtime.make`
does not choose storage implicitly. `runtime.bytes` is the platform's Effect-native
byte service: reads return a `ByteSource` with metadata and a byte stream. Blob
storage classifies driver failures at its storage boundary.

`runtime.connectivity.online` reads the current connectivity hint, while
`runtime.connectivity.changes` streams the initial state and subsequent changes.
The stream keeps only the latest state for a slow consumer. Platform listeners
and browser reconnection stabilization belong to the Layer's Scope. Connectivity
is a hint; individual requests can still fail while the device reports online.

Browser authentication is also scoped. `browserAuthentication.start(...)` acquires
a session, and `session.open(url)` waits for its callback. Closing or interrupting
the session's Scope closes its popup, native session or loopback callback listener.
There is no separate session `close()` API. On web, acquisition reserves the popup
synchronously; the UI bridge starts that Effect before awaiting OAuth/RPC work.

`persistEncryptionKeys: true` permits a non-extractable AES key to persist in
IndexedDB. Same-origin JavaScript can use it to decrypt; this is not a vault lock
or XSS protection. Individual property decrypt calls still default to `cache: false`.
Without that flag, a persistent browser runtime needs a separately composed keyring
before it can persist credentials.

## Shared browser ownership

Issue-tracker opens one SharedWorker per installation. Connect, token refresh,
backend sessions and persistent ontology partitions live there. The page uses
Effect RPC for installation/authentication operations and subscribes to connection
snapshots; it opens only memory replicas and byte caches. Browser authorization
presentation remains in the page. Neither storage broadcasts nor shared-table
access from tabs are needed.

`serveInstallationWorker` and `connectInstallationWorker` are in
`@party-stack/ontology-server/installation/worker`. They multiplex ontology RPC
alongside trusted same-origin installation controls. Pass an `open` Effect to
start the transport before installation acquisition; clients receive typed startup
failures. An already acquired installation is also accepted. They are not public server
authentication endpoints. Public HTTP clients use the authorized ontology protocol.

For a server that already owns its authentication/installation lifecycle,
`connectLiveOntology` / `createConnectedLiveOntology` and `serveOntologyWorker`
remain the lower-level ontology composers. They accept platform/transport Layers;
Runtime itself has no ontology or TanStack dependency.

## Trace recording

Tracing is not a platform Runtime capability. Replica, storage and adapter Effects
produce spans through Effect's standard `Tracer`. Devtools capture is opt-in and
also forwards spans to any configured Effect tracer, including an OTel exporter.
No OTLP collector is required to use the panel. Ordinary ontology constructors
default to no devtools capture; `traceRecording: "buffer"` enables local history,
and `traceRecording: "live"` emits updates without retaining completed traces.
Native Effect compositions can supply the `TraceRecording` configuration instead.

The capture implementation is a separate `@party-stack/runtime/tracing` export.
Buffered history retains up to 500 spans; both modes limit diagnostic events to
100 per span and filter attributes. Action parameters are not trace payloads.
Producers mark displayable events explicitly.

`serveInstallationWorker` enables live capture by default when acquiring its
`open` Effect; `connectInstallationWorker` enables local tab history. Either helper
accepts `traceRecording: false`. An already acquired installation must have capture
configured when it was acquired. No ontology configuration leaks into WebRuntime.

To inspect its parent's work, devtools uses our authorized ontology-server `Traces`
streaming RPC. The worker publishes span updates; the tab merges them into a
bounded 500-span history. The worker retains no completed history in live mode,
so work finished before subscription is unavailable. Transport queues are bounded,
and diagnostics are best effort under overload. Closing the final subscriber
stops its RPC stream. Effect RPC supplies transport and cancellation.

Clear removes the selected source's history in the inspecting tab. It does not
clear another tab's view, cancel work, or change replica data. Subsequent span
updates can appear normally, including updates from an ongoing operation.

See [installation and setup](/docs/getting-started) for examples. Worker failure
does not silently start a second persistent owner. Choose memory-only or another
placement explicitly when the required browser facilities are unavailable.
