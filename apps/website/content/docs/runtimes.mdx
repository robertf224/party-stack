## Available today

`@party-stack/web-runtime` provides a scoped Runtime Layer. The containing Effect
scope owns connectivity subscriptions, storage resources, channels, and host locks.

```ts
import * as WebRuntime from "@party-stack/web-runtime";

const persistent = WebRuntime.layer({
    owner: userId,
    namespace: ontologyId,
    storage: "indexeddb",
    persistEncryptionKeys: true,
});

const isolated = WebRuntime.layer({
    owner: userId,
    namespace: "isolated-view",
    storage: "memory",
});
```

Persistent mode uses IndexedDB tables, OPFS bytes, and a lifetime Web Lock for
host ownership. It requires those browser facilities. Memory mode is isolated.

`persistEncryptionKeys: true` explicitly permits persistent device encryption
keys. Same-origin code can still use those keys; this is not protection from
malicious same-origin JavaScript. Property decryption separately defaults to
no plaintext caching unless the caller opts in.

## The issue-tracker topology today

Each identity/installation/ontology partition opens one persistent SharedWorker
owner. Tabs use memory replicas and delegate attachment operations to that owner.
The worker handles persistent blob metadata and bytes. Tabs query their own
materialized collections.

Application setup currently assembles too many pieces: RPC, replica construction,
mutator execution, attachment helpers, tracing, and lifecycle handling. The
proposed infrastructure helper should own those details.

## Proposed application setup

**Design proposal — these constructors are not exported yet.**

Browser integration helpers would live under `web-runtime/tab` and
`web-runtime/shared-worker`. They would use a platform-neutral scoped ontology
client composer in `ontology-server/client`. The platform-only `web-runtime`
entry point would remain separate from these higher-level integrations.

```ts
import * as Tab from "@party-stack/web-runtime/tab";

// Proposed: the app chooses placement and domain behavior.
const open = Tab.open({
    partition,
    worker: (name) =>
        new SharedWorker(new URL("./ontology.worker.ts", import.meta.url), { name, type: "module" }),
    ir,
    mutators,
});
```

`open` is a scoped Effect, acquired within the application's owning scope. The
application still supplies a bundler-visible worker URL, principal partition,
and domain implementation. Infrastructure composes the local replica and view,
delegates attachment operations by default, and closes the connection and derived
resources with the scope. A convenience Promise bridge belongs at the application
edge when required by React integration.

Worker startup fallback must happen before accepting writes. A failed connection
does not authorize silently creating a second persistent owner. A configured
in-process fallback acquires the same namespace lock. Persistent platform storage
being unavailable needs an explicit application policy; it must not silently
turn durable acceptance into memory-only acceptance.

See the [replication proposal](/docs/design/replication#runtime-composition)
for the full package split and lifecycle plan.
